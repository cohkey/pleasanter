### 標準Group宛先の事前検証

通知エンジンの実装前に、標準notifications.New / SendでGroup宛先の展開結果をOutgoingMailsに記録して確認した。SMTPホスト未設定を確認したうえで実施し、外部メール配送は行っていない。正常配送の検証ではない。

| 入力 | 展開結果 |
| --- | --- |
| 1メンバーのGroupをToへ指定 | そのユーザーの登録メール1件 |
| 2メンバーのGroupをToへ指定 | 両ユーザーの登録メール2件 |
| Group＋User＋同一メールを同じToへ指定 | 同一To内で重複排除 |
| 同じメンバーを含むGroupをTo/Cc/Bccへ指定 | 各欄には残る。欄をまたぐ重複排除なし |
| 空のGroup | 送信レコード生成なし |
| 無効のGroup | 送信レコード生成なし |

APIで一時グループを短時間に連続作成した直後には一部の新規Groupが宛先へ展開されなかった。専用アプリを再起動してキャッシュを更新した後、全ケースが成功した。新規GroupがDBにあるだけで通知可能と判断せず、標準Group宛先の反映も確認すること。通常運用で常に再起動が必要という結論ではない。

### 通知エンジンの検証

リンク選択式の店所ClassA、GM区分ClassC、実際のNumAを持つ一時対応表を作成。通知対象ClassDの3区分とClassBの共用を、親ルールのリンク付きで確認した。

| 更新条件 | 結果 |
| --- | --- |
| 通常店所：既存組織＋客サGM＋固定組織の3ルール | 各ルール成立。既存組織メール・Group1件・固定組織メールを生成 |
| 特殊店所：同じ3ルール | 客サGMは第一〜第三の3件を取得 |
| 他店所／類似するGM区分を併設 | 宛先に混入しない |
| 固定組織 | 両店所で同じ組織コードのメール通知設定を利用 |
| 終了ログ | 候補3件／成立3件／不成立0件 |
| SEND_ENABLED=false | 各ルールで未送信と明示、OutgoingMails生成0件 |

複数Groupの並び順は取得順を維持し、並びを整えるためのソートは加えていない。期待する宛先集合で検証した。
